# Architecture

## Design goal

React AI Grounded Responses sits between an AI-producing system and the end-user interface. The application supplies response text, source metadata, claim ranges, and evidence spans. The library validates structural relationships and exposes a stable snapshot; it does not retrieve documents, invoke a model, or decide semantic truth.

## Components

1. **Core data model** — Source, Claim, EvidenceSpan, response/source ranges, structural integrity issues, and optional application-supplied semantic review.
2. **Offset utilities** — explicit UTF-16 and Unicode code-point conversion. All public ranges are zero-based and end-exclusive.
3. **Integrity validator** — checks source existence, range validity, source versions/fingerprints, quote matching, and claim text against its response range.
4. **Observable ledger** — holds response text, sources, and claims; recalculates validation when data changes; caches immutable snapshots for useSyncExternalStore.
5. **Streaming citation parser** — parses numeric markers in complete or incremental text and buffers incomplete numeric markers across chunk boundaries.
6. **React adapter** — renders response segments and highlighted source evidence without imposing a style system.

## Data flow

1. The application receives AI output and structured source metadata from its provider or RAG pipeline.
2. It creates a ledger with the current response text and sources.
3. It attaches claims whose response ranges and evidence spans come from trusted upstream metadata or explicit application processing.
4. The ledger recomputes structural validation whenever response text, sources, or claims change.
5. React consumers render the snapshot and can select claim segments to inspect related source material.
6. If the source version or fingerprint changes, old evidence is flagged as stale instead of being silently accepted.

## Trust boundaries

Model output and provider metadata are untrusted input. Numeric citation parsing provides a reference index only; it cannot prove that the index refers to the correct source. The application is responsible for mapping indices to source IDs and for handling unknown or duplicate references.

A structural status of valid means that the supplied relationships passed deterministic integrity checks. It is not a semantic entailment verdict. SemanticReview is a separate optional data field and is never generated by the core.

## Offset contract

Offsets are zero-based, with an inclusive start and exclusive end. The default unit is JavaScript UTF-16 code units. Inputs using Unicode code points must set offsetUnit to codePoint. Conversion functions reject invalid or out-of-bounds ranges rather than guessing.

Quotes are compared exactly by default. An application may inject a normalizeQuote function for narrowly defined comparisons. Normalization must not be used to silently reinterpret source offsets; offsets always refer to the source text supplied to the validator.

Source fingerprints are deterministic, non-cryptographic change-detection hints. They are not security hashes, signatures, or proof of document authenticity.

## React and Next.js

The core package does not import React or access browser APIs. The React adapter is a separate export and uses the public useSyncExternalStore API.

For Next.js App Router, create and validate data on the server if appropriate, then pass a serializable GroundedResponseSnapshot to GroundedResponse. Do not pass a class instance such as GroundedResponseLedger from a Server Component into a Client Component. Live ledgers belong in client-side code. The consuming app should test its actual SSR, hydration, and production build.

## Current constraints

- Numeric citation parsing recognizes a deliberately small textual format: bracketed positive decimal digits.
- Parsing does not resolve source IDs; provider adapters are a future extension.
- The core does not call LLMs, retrieve sources, or score semantic entailment.
- The React components provide structure and data attributes, not a design system or chat UI.
- The source fingerprint is non-cryptographic and must not be used as a security boundary.
